### 1. Reduce unnecessary pass boundaries for proven safe barrier cases

`/Users/hanbinnoh/Documents/dxmt-d3d12/src/d3d12/d3d12_command_list.cpp:5870-5914` explicitly describes deliberate over-synchronization and unconditionally calls InvalidateCurrentPass after each nonempty valid ResourceBarrier call, including transition-only batches. This is a static fact, not inferred from logs. `.../d3d12_command_allocator.hpp:170-177` closes the current recorded pass by linking it and setting encoder_current=null; it does not itself wait on CPU. The next PreDraw opens a new render encoder and rebuilds attachments with Load/Store (`.../d3d12_command_list.cpp:1881-1976`); the compute equivalent dirties root arguments/signature and PSO (`:3662-3672`). Queue code ends render work with updateFence/endEncoding (`.../d3d12_command_queue.cpp:6050-6054`) and compute work with waitForFence/encodeCommands/updateFence/endEncoding (`:6400-6425`).

Mechanism: unnecessary encoder boundaries can add Metal encoder setup, attachment store/load traffic, fence dependencies, pipeline/root/static-sampler rebinding, and CPU command nodes. This is the strongest ordinary steady-frame GPU/CPU optimization **hypothesis** in this axis. Minimal initial candidate is classifying truly read-to-read or otherwise no-dependency transitions and retaining the encoder only when proven safe. A blanket removal of barriers is wrong: resources use untracked Metal storage, UAV/aliasing dependencies require ordering, render-pass conformance is enforced, split barriers have contracts, and reserved-resource alias coherence needs additional work. The existing in-encoder memory-barrier implementation at `.../d3d12_command_queue.cpp:5998-6003` demonstrates a local primitive, not proof that it can replace all legacy barriers.

Exact static bound: B nonempty ResourceBarrier calls can close at most B currently open passes; repeated calls with no current pass do not each create an encoder because InvalidateCurrentPass early-returns. No latest-run B count exists. Do not claim one encoder per resource barrier element.

### 2. Remove repeated ordinary descriptor-table traversal where shader/resource contracts permit

`/Users/hanbinnoh/Documents/dxmt-d3d12/src/d3d12/d3d12_command_list.cpp:1761-1805` captures descriptor tables at PreDraw/PreDispatch, including scanning root parameters/ranges and linear searching the pass's previous uses. The call is outside dirty-root checks (`:2303-2304`, `:3738-3739`), so unchanged-root draws still repeat these CPU scans, although retained table entries are deduplicated. `.../d3d12_command_queue.cpp:3441-3502` then traverses each captured ordinary table's full SRV/UAV ranges; only `restrict_to_shader` tables take the shader-used interval path. Directly indexed heaps traverse every descriptor once per collection after validation/deduplication.

Each live texture descriptor incurs owner lookup at `.../d3d12_command_queue.cpp:3443-3452`; `.../d3d12_device.cpp:2983-2989` takes swizzle_texture_lock_, searches descriptor_resources_, checks owner_id and TryAddRefPrivate. `AppendStandardTexture` then checks view properties, and only relevant swizzle/cast/MSAA/volume resources remain (`.../d3d12_command_queue.cpp:3368-3430`). Normal textures thus still incur discovery work even when they need no conversion. With S eligible descriptors in a pass, this collection performs S descriptor visits and up to S owner lookups; overlapping ordinary table ranges may visit the same descriptor repeatedly. Linear append/dedup work can grow with collected uses, but not every ordinary texture is appended.

Minimal alternatives, in order: (a) reuse the existing ForEachUsedDescriptorRange path for ordinary non-atomic tables if correctness and dynamic indexing allow it; (b) skip unchanged-root capture work with a per-pass capture-valid condition that includes pipeline-sensitive atomic bindings; (c) deduplicate overlapping table intervals within one collection; (d) only if profiles show the mutex dominating, consolidate validated lookup under one safe snapshot/lease. Do NOT cache stale resource pointers across descriptor writes, alias lifetime changes, queue submissions, or allocator resets. These are static CPU-cost candidates, not measured hotspots.

Important existing-fix counterclaim: commit **8cb958a2edd03fda46b131d344585e9fa7ef48f6**, `perf(d3d12): deduplicate bindless heap collection` (2026-10-07), already prevents repeated full-heap scans across directly indexed root signatures in one collection. Executed git show confirms the seven-line guard in queue collection and a corresponding atomic64 change plus CPU regression fixtures. Recommending that same fix as new work would be stale. It does not deduplicate ordinary table traversal or scans across separate render/compute passes.

### 3. Reuse immutable static-sampler uploads within one recording

`/Users/hanbinnoh/Documents/dxmt-d3d12/src/d3d12/d3d12_command_list.cpp:3628-3655` copies **8 × UploadQwords × Count bytes** for root arguments and **64 × NumStaticSamplers bytes** for static samplers into 64-byte-aligned allocator storage. Dirty gating prevents this for every unchanged draw (`:2180-2215`, `:3712-3735`), but new encoders dirty both signatures and arguments, multiplying these copies after barriers. The smallest candidate is retaining one allocator-recording-local static-sampler offset per immutable root signature and rebinding it after encoder changes, while keeping dynamic roots copied according to D3D12 semantics. Prefer barrier reduction first because it also removes rebinding and attachment cost.

Counterclaim: these blocks are small, and current allocation is a bump-pointer fast path. `.../d3d12_command_allocator.hpp:311-320` uses existing GPU chunks when capacity fits; `.../d3d12_command_allocator.cpp:135-140` returns without native allocation in that case. CPU commands use aligned bump allocation and a linked command stream (`.../d3d12_command_allocator.hpp:204-268`). malloc/newBuffer occurs at chunk growth (`.../d3d12_command_allocator.cpp:159-171`) or CPU heap spill (`.../d3d12_command_allocator.hpp:211-215`), not every root upload or draw. A generic object-pool/arena rewrite would duplicate existing functionality and is unsupported.

### 4. Optimize actual conversion/copy traffic only after identifying its activation

Ordinary CopyBufferRegion records two state uses, enters/reuses PreBlit and records one native GPU buffer copy (`/Users/hanbinnoh/Documents/dxmt-d3d12/src/d3d12/d3d12_command_list.cpp:3814-3873`). There is no ordinary per-copy CPU memcpy of the payload. Predication uses a specialized compute path, and actual texture format/planar/D24/cast/MSAA/reserved paths have extra conversion work, but the latest log has no activation or byte totals.

Source confirms real expensive special cases: buffer render targets allocate a private staging texture per pass (`.../d3d12_command_list.cpp:1928-1964`) and queue code performs buffer-to-texture then texture-to-buffer copies (`.../d3d12_command_queue.cpp:5865-5890`, `:6055-6076`); active visibility queries allocate a scratch buffer per pass (`.../d3d12_command_list.cpp:1896-1915`) and one compute accumulation encoder per visibility target (`.../d3d12_command_queue.cpp:6079-6113`); swizzle/cast/MSAA resources receive Begin/EndStandardSwizzlePass around render/compute (`:5785-5818`, `:6424-6431`) and lazy helper pipelines (`:3505-3533`). Atomic64 PSOs force pass invalidation before every relevant draw/dispatch (`.../d3d12_command_list.cpp:1843-1844`, `:3661`) and specialized queue phases. Geometry/tessellation/MSAA emulation can add capture/replay passes. None is established as active or hot in the latest city run. Recommendation: count actual conversions, bytes and active feature paths before touching these contracts; do not disable them to manufacture faster wrong rendering.
