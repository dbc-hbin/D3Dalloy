## Lead 1 — Present1 dirty rectangles: NOT recoverable (schema gap, not just opt-in)

Absence is twofold and independent:

1. **The trace schema has no dirty-rect field.** `present_request` is the only swapchain trace event (`src/d3d12/d3d12_swapchain.cpp:1450-1455`) and records exactly `swapchain`, `frame`, `index`, `resource`, `sync_interval`. It does not record `DirtyRectsCount`, the rect list, `composition.full`, or the swap effect. `present_encode` (`d3d12_command_queue.cpp:7322-7323`) records only `queue`, `submission`, `resource`. So even a correctly configured trace cannot answer this lead today; a code change would be required.
2. **No run captured even that.** Live `ZenlessZoneZero_d3d12.log` has zero `OWNED_GRAPHICS_*` lines (grep for `OWNED_GRAPHICS|Present|present|reset|alias|dirty|hash|width|height` = no matches); candidate-03 has zero `present_request`/`transition`/`execute_list`/`aliasing_barrier` matches because its 64-event budget was consumed by pipeline-cache/compute events (max observed `event_id` = 64 at `ZenlessZoneZero_d3d12.log:66`).

Mechanism for the record: `d3d12_swapchain.cpp:1293-1318` copies caller rects into `composition.dirty_rects` and sets `full=false` only when `DirtyRectsCount > 0`; flip-discard rejects dirty rects outright (`:1296-1297`), and the incremental path exists only when `present_history_` was created, i.e. only for `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` (`:988`). `d3d12_command_queue.cpp:7260-7277` then blits previous-full + caller rects. **Swap effect itself is never logged**, so even the precondition (flip-sequential vs flip-discard) is undetermined for both runs.

## EXPAND

- **LEAD (highest value, cheap):** enable `OWNED_GRAPHICS_TRACE=1` with a limit above the observed event count (candidate-03 needed >64 and the counter is per-DLL) on a bounded reproducer. That single flag turns four of these six leads from absent into observed: `temporal_record`/`temporal_encode` (reset churn, resource ids), `aliasing_barrier`, and `present_encode`. It still will not answer dirty rectangles or content freshness.
- **LEAD (schema work, only if those leads stay live):** add dirty-rect count / `composition.full` / swap effect to `present_request`, and add the `Reset`/`ResetHistory` flag to `ngx_d3d12_evaluate_parse`. Until then Present1 rects and DLSS reset frequency are unfalsifiable from logs by construction, not merely uncaptured.
- **LEAD (content freshness):** the only existing mechanism is a Metal capture (`MTL_CAPTURE_ENABLED=1` + `DXMT_CAPTURE_EXECUTABLE` + `DXMT_CAPTURE_FRAME`), which produces a trace, not a per-frame content hash; a decisive input→output freshness test needs either that capture or a new bounded readback/hash event.
- **LEAD (shader pairs):** set `DXMT_SHADER_FAILURE_PATH` on the next run to obtain current pair identities and module+offset callers; only then can the historical 64-pair replay result (`precompile-run-03/shaders/`, `precompile-run-01/binding-diagnosis`) be applied to the 9,131 latest lines. Note the 64-identity cap will again capture only the first 64 distinct pairs.
- **DEAD END:** treating the live watermark 3840x2160 as the render/SR output resolution, or comparing it against the historical 1280x720 as a proven workload difference.
- **DEAD END:** using candidate-03's `present_id=1…14559` freshness series, its two stills, its 11-evaluation NGX window, or its 64-event trace as evidence about the live run's temporal output.
- **DEAD END:** inferring underlying alias overlap from the latest-only `[ffx] Upscaler Context … aliasableUsageInBytes` line; it has no resource identity and self-inconsistent units.
- **DEAD END:** inferring feature-reset churn from the single historical NGX create sequence or from app-level `reset` strings (none exist in either Player.log except the Metal HUD menu item).
- **Precise uncaptured-data gap (all six leads):** for the live run there is no trace-enabled sink, no nvngx sink, no swapchain/backbuffer dimension record, no dirty-rect or swap-effect record, no failed-pair hash or caller stack, and no frame content/identity series.
