## API/device parity result

Two bounded differences are confirmed: native descriptor view-pool range batching is missing, and the versioned root-signature deserializer lacks the reference's null-output-pointer rejection. The first is a CPU-work optimization on an ordinary game rendering path; the second is an invalid-call robustness defect, not an established game blocker. No missing SM6.6/FL12_2 admission, Device14 root-signature creation, query-heap factory, or lifetime/protected/meta-command implementation was established.

Authority: read-only current source versus static decompiled D3DMetal for SHA256 `f5b56df1b8fe8b364dd9530651a3769c8aed948bd343be3b4510604d503e2bad`. Retained `build/local/d3d12-gap-rea-20261010/coverage-final.json` supplies historical shipped-artifact function evidence, not current runtime proof. New REA queries read function bodies without opening, closing, switching, or annotating the shared target. CORE's SM6.6/conditional FL12_2 section and its 18-of-19 optimization ledger were consulted; the discovery inventory was not treated as full-surface support evidence.

### Confirmed gap 1: batch native descriptor view-pool copies

**Reference behavior.** `D3D12Device::CopyDescriptorsSimple` at `0x6c2e2` calls `copyResourceViewsFromPool:sourceRange:destinationIndex:` once for the requested descriptor count, copies the CPU descriptor records and rebases resource IDs that lie inside the source pool range. Full evidence ID: `ev_163eaed324d3ac384a3d8c47d458119006f7141fcc94cc8203225ae3ff04213a`. `CopyDescriptors` at `0x6c538` also has a one-destination-range fast path that batches each source range; full evidence ID: `ev_93f45169e3b071383aab611d8efd10247caf48f8aba8b4ffd8b8782861a5ae21`.

**Owned counterpart.** `src/d3d12/d3d12_descriptor_heap.cpp:636-653` loops through the copy count and calls `copyTextureView` for each texture slot. `src/winemetal/Metal4.hpp:43-44` invokes the WMT bridge once per slot; `src/winemetal/unix/winemetal_metal4.c:787-793` acquires the pool locks and calls the native range-copy API with `NSMakeRange(a[2],1)`. Thus N texture descriptors cause N bridge/native copy operations and lock pairs rather than a single eligible range copy. The existing implementation explicitly preserves overlapping-copy order and fallback pools; those properties must remain.

**Game-path relevance.** Ordinary CBV/SRV/UAV descriptor-table rebuilding and bindless heap population use these public copy calls. This is not a new feature unlock: it reduces CPU bridge and native-call work when copying contiguous texture-view descriptors. No named game's call frequency, frame-time benefit or FPS improvement was measured.

**Minimal independent implementation.** Batch eligible contiguous texture runs only when both native pools exist and source/destination ranges do not overlap. Make one range-copy bridge call, rebase the run's native IDs and retain/update destination parent ownership using existing metadata. Keep the current per-slot path for overlap, mixed fallback/native pools and unsupported runs. Do not rewrite the entire descriptor representation or claim a missing unified pool. Start with the heap helper; a separate device-level single-destination fast path is optional only if profiling still justifies it.

**Focused regression.** Extend the existing `descriptor-view-pool` lane in `graphics-translator/tests/owned-d3d12-bindless.cpp:847-906` with a contiguous cross-heap texture range and a deterministic native operation-count assertion. Preserve its same/cross-heap, overlap, overwrite, null, resource-generation and source-release GPU oracles. Require one range operation for the eligible run and preserve byte/numeric results; do not merely weaken the existing trace budget.

### Confirmed gap 2: null output pointer in versioned deserialization

**Reference behavior.** `D3D12VersionedRootSignatureDeserializer::GetRootSignatureDescAtVersion` at `0x76b4c` explicitly returns `0x80070057` (E_INVALIDARG) when the output descriptor pointer is null, otherwise stores a descriptor pointer and returns success. Full evidence ID: `ev_fc48714c90ee775eb0a8811248766dfc3a3ac49ca96d076818bad3e9e8c6a02c`.

**Owned counterpart.** `src/d3d12/d3d12_root_signature.cpp:521-537` switches on version and unconditionally dereferences `ppDesc` for valid versions 1.0, 1.1 and 1.2. Passing a valid version with a null output therefore dereferences null rather than returning the reference error. Actual conversion is already implemented; do not report it as absent.

**Game-path relevance.** This function participates in root-signature inspection/conversion during engine startup, but valid callers provide an output pointer. No actual game's null-output call was observed. Treat this as low-priority public API robustness, not a game-enabling feature or hot-path optimization.

**Minimal independent implementation.** Add a single `if (!ppDesc) return E_INVALIDARG;` before the version switch. Add null-output assertions to the existing version-conversion section at `graphics-translator/tests/owned-d3d12-bindless.cpp:1638-1662`, keeping current 1.1/1.2 conversion and invalid-version expectations.
