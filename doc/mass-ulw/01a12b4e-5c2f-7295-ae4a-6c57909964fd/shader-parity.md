## Shader/binding parity result

One narrow, statically confirmed configuration gap: current D3D12 pipeline compilation does not enable the already-implemented sample-NaN-to-zero option, whereas D3DMetal enables its corresponding compiler compatibility bit by default. This is not a new shader compiler feature, an FPS optimization, or a demonstrated fix for a named game. Geometry/SO, tessellation, AS/MS, wave lowering, typed-buffer addressing, sampler metadata, and binding dirty tracking already exist; none should be reintroduced as missing work.

All observations below are static. No builds, GPU runs, annotations, target switches, or product edits were performed. REA observations identify the requested D3DMetal x86_64 Mach-O SHA256 `f5b56df1b8fe8b364dd9530651a3769c8aed948bd343be3b4510604d503e2bad`, provider Ghidra 12.1.4. D3DMetal delegates actual shader translation to imported libmetalirconverter routines; a wrapper invoking an option does not establish the external compiler's full numerical semantics.

### G1: D3D12 fails to enable existing sample-NaN compatibility policy

**Reference body evidence.** `D3DMCompiler::D3DMCompiler` at `0x9abba` executes `getenv("D3DM_SAMPLE_NAN_TO_ZERO")`; absent an override, its default is true, stored at object offset `0x54d`. Full Evidence ID: `ev_68fdf454b02a252530ecf2483f7e5445d7edfb8cd1ea1dfc35c88fed84ae574e`.

`D3DMCompiler::CreateIRCompiler` at `0x87c36` combines `this[0x54d] << 5` into the flags supplied to `_IRCompilerSetCompatibilityFlags`. Full Evidence ID: `ev_ef3a7d8f17723968210410e5373479b0c7b6f5e175b375762af7622e1279ee47`. The compute-stage wrapper `0x879e8` obtains that configured compiler and calls `CompileAndLinkStage`; full Evidence ID `ev_e1100174be28390f482f08269a446769d66ffeb06ec51b5c855e7bcaca03fa9c`. The latter's body at `0x87e4a` creates the DXIL object, installs the root signature and invokes compile/link; full Evidence ID `ev_b71b332997132827640e901d5de158f3d5b5f906d5b9a82d504241ee34cbb10f`.

**Owned counterpart.** Ordinary graphics `src/d3d12/d3d12_pipeline_graphics.cpp:1636-1640` and compute `src/d3d12/d3d12_pipeline_compute.cpp:90-94` explicitly initialize `common.flags` to zero. Additional graphics compile branches value-initialize `common`, e.g. mesh at `:801`, GS/tessellation at `:929`, and statistics/index-pull variants at `:2032`, `:2172`, `:2233`, `:2319`, `:2427`. DXBC compilation passes the flag into AIRBuilder at `src/airconv/dxbc_converter.cpp:1009`; DXIL does so at `src/airconv/dxil_signature.cpp:1707`. AIR sample construction at `src/airconv/nt/air_builder.cpp:1530-1534` selects either sanitized or unchanged coordinates. Grad construction similarly sanitizes derivatives at `:1754-1756`. Sanitization itself is already implemented at `src/airconv/nt/air_builder.hpp:627-628`, using the bitwise NaN detector at `src/airconv/nt/air_builder.cpp:3166-3176`.

**Actual game-path relevance.** This lies on normal public D3D12 PS/CS shader compilation and sampled-texture instructions, not an unused diagnostic/export path. It matters when a real shader supplies NaN coordinates/derivatives, including values derived from degenerate math. No retained game shader or trace read in this assignment proves that ZZZ or another named game exercises that condition. The confirmed fact is the default-policy difference; user-visible impact and priority remain unverified.

**Minimal independent recommendation.** Enable the existing `SM50_SHADER_FLAG_SAMPLE_NAN_TO_ZERO` at the D3D12 common-argument construction sites, consistently across ordinary and lazy/mesh/statistics variants; do not add a second sanitization pass or copy reference code. Preserve D3D11 policy. Verify existing artifact keys include common flags and invalidate the compiler cache version if necessary. Do not simultaneously implement positive-INF flushing or application-specific fragment-output NaN policies: their exact external semantics are not established here.

**Focused validation.** Extend the existing `graphics-translator/tests/owned-d3d12-dxil-texture.cpp` fixture with finite, quiet/signaling NaN coordinates and NaN gradients in ordinary public PS/CS pipelines, using independent expected texels at zero coordinates; include finite-controls and cached/lazy variants. Existing fixture currently contains no NaN/Inf sampling test. Add DXBC coverage alongside it rather than testing AIRBuilder in isolation. After fixture/runtime production, a focused runner command is:

```sh
python3 scripts/test-owned-graphics.py --runtime "$RUNTIME" --fixture "$DXIL_TEXTURE_FIXTURE" --dxil-dir "$DXIL_DIR" --suite dxil-texture --mode no-present --validation --out "$QA_OUT"
```

Those environment variables must identify the freshly built, architecture-compatible runtime/fixture/input/output paths. This is a recommended future command, not a command executed or a claim that the current suite detects G1. The generic runner's FEX architecture gate must not be bypassed; the main agent must select the documented direct FEX route where required.
