## Cache/allocation parity result

The three optimization families confirmed by the initial audit are now implemented: stage-granular artifact persistence, off-thread automatic disk publication, and RT/WG immutable compilation-result reuse. Commit-time Present reservation is also implemented through a cancelable native ticket. Stage keys, in-process stage/library sharing, specialization, single-flight, allocator recycling, hashed resource views, and Metal4 argument-table/residency reuse already exist. General device-wide native PSO sharing remains an exact unknown on the reference side, not an invented gap.

Authority: all fresh REA bodies identify D3DMetal SHA256 f5b56df1b8fe8b364dd9530651a3769c8aed948bd343be3b4510604d503e2bad, x86_64, Ghidra 12.1.4. These are shipped-artifact/static observations, not game execution or performance measurements. The shared target was not opened, switched, closed, or annotated.

### Implemented gaps and retained REA evidence

#### 1. Persist immutable artifacts by stage key, not only whole-PSO key

Reference bodies: compute producer `0x879e8`, evidence `ev_e1100174be28390f482f08269a446769d66ffeb06ec51b5c855e7bcaca03fa9c`, takes the stage-cache key, sets result ID at `+0x170`, and schedules stage serialization. Writer `0x88240`, evidence `ev_8a6296fb454b6d3cac4163245ab9a72648b1c647307dfa8ff73295e98f0bd95d`, writes a record containing the 24-byte compute key, entry name, metallib bytes and serialized reflection, with aligned regions and checksum. Restore `0x93826`, evidence `ev_b4a6fe7b1b7487da23e4483522892db4e11b1cf220d1a6fb548f387183be85aa`, validates record length/footer/checksum, reconstructs library/reflection in case 8, and repopulates the compute-stage map. `D3DMPipelineStagesCache::Open` `0x85468`, evidence `ev_cited_below_unavailable`, was read and resolves persisted PSO stage IDs against stage caches; its exact ID was not retained in this report, and is unnecessary to establish the gap.

Owned counterpart: `DeviceShaderArtifactCache::Compile` at `pipeline_cache.cpp:634-691` retains canonical stage key -> immutable library/constants/relocations/metadata solely in `ArtifactCache`. `PipelineCache::GetBlob` at `:1184` serializes complete-PSO storage, and `d3d12_pipeline_graphics.cpp:1628-1631` explicitly excludes mesh variants from ordinary-stage serialization. This is not absence of disk caching: exact VS/PS/CS PSO reopen already works.

Game-path relevance: ordinary `CreateGraphicsPipelineState`/`CreateComputePipelineState` with changed raster/blend state but unchanged stage inputs can reuse AIR within one device and, when the stage record is valid, across processes. GS/HS/DS/mesh lazy variants now use the same bounded artifact representation while native objects remain process-local. Structural creation/draw paths are verified; no measured game cold-start benefit or particular game's cross-session duplicate rate was observed.

Implementation: the existing canonical-key boundary now performs bounded stage-artifact lookup/publication. `ShaderStageArtifact` bytes and output metadata are serialized without LLVM handles or native pointers; identity/checksum/atomic-publication rules and generation invalidation remain enforced.

Focused checks: `python3 graphics-translator/tests/run-pipeline-cache-cpu.py` passes stage persistence, corruption, generation, worker, and retry gates. GPU execution remains blocked by the retained ARM64X runtime versus the fresh plain-ARM64 build mismatch.

#### 2. Move automatic disk publication off the PSO producer's return path

Reference compute producer `0x879e8`, full evidence `ev_e1100174be28390f482f08269a446769d66ffeb06ec51b5c855e7bcaca03fa9c`, calls `_dispatch_async` for the separate stage-file writer after successful compilation. The actual file-writing block `0x88240` is evidence `ev_8a6296fb454b6d3cac4163245ab9a72648b1c647307dfa8ff73295e98f0bd95d`.

Owned counterpart: `PipelineCache::Complete`, `pipeline_cache.cpp:919-938`, now publishes the memory flight and queues a bounded joined worker. The worker retains generation/exact-blob checks, cross-process accounting, eviction, `FlushFileBuffers`, and atomic rename. `CreateComputePipelineState` and graphics still call Complete before returning, but no longer wait for optional disk I/O.

Game-path relevance: game-created cold PSOs can enqueue optional disk work during loading or streaming without holding the creation caller on file I/O. This is a scheduling improvement inferred from the call chain, not a measured stutter cause or FPS gain.

Implementation: one bounded owned publication worker retains immutable blob/key/generation; no detached per-PSO threads are used. Exact-blob retry checks, clear/disable ordering, bounded retained memory, cross-process accounting, and shutdown draining are preserved. Only automatic persistence is asynchronous; the application's StoreValue contract stays synchronous.

Focused checks: `python3 graphics-translator/tests/run-pipeline-cache-cpu.py` passes delayed publication, generation/clear/disable/retry, bounded queue, and worker-shutdown gates. A separate WinAPI runtime publication run was not available in this host.

#### 3. Reuse RT/WG compilation results and native libraries

Reference RT `0x996d8`, full evidence `ev_8ea14a1e75a5a464e3c4121437117200f6a89a5b8139db2a92f77c7bbec1e0d3`, builds a key covering bytecode, global/local roots, entry-name set, RT configuration and raygen mode; calls lookupOrCreate on map `+0x318`; a hit waits/returns existing result and only a miss invokes the compiler. Producer `0x99ec4`, evidence `ev_deb0f5dbbe3d88dee1ed15a3cfa12aec05192d1f873242d29936f06df0b151f0`, compiles metallib/reflection and asynchronously persists it.

Reference WG `0x9cfb6`, evidence `ev_143ac8bcdd3f2d1593883b61da16787d84140ea47da92286d25a78a7c90e663d`, constructs NodeStageCacheKey from bytecode/export and node descriptor data, queries the node map at `+0x360` under lock, consumes existing ValueWrapper on hit, and publishes a newly compiled result on miss. Producer `0x9d940`, evidence `ev_49a457513daf4c0c30061a48812b542e44dfab89787d91f3d3a47936863c3a43`, configures node descriptors/overrides/local root, compiles stage `0x11`, and dispatches serialization.

Owned counterpart: RT `state_object.cpp:810-829` and WG `work_graph.cpp:815-825` now call `DeviceShaderArtifactCache`, which caches the complete compiler output but still creates state-object-local native libraries/functions/pipelines. Existing RT exports share one library within their state object and WG AddToStateObject can preserve parent nodes; the added cache targets repeat/new-object compilation across equivalent descriptions without sharing mutable native state.

Game-path relevance: RT state-object creation feeds actual DispatchRays, so equivalent state objects/collections can repeat compiler and loader work. WG state-object creation feeds DispatchGraph. No particular current game was observed recreating these descriptions; WG relevance to the user's current game is unknown and should remain lower priority until demonstrated.

Implementation: RT stores a device-owned full canonical pipeline-description artifact containing metallib, constants/relocations, function metadata and copied function-name storage; the compiler emits a merged whole pipeline, so this does not fake per-export reuse. WG stores the full compile description and returned node metadata. Both include compiler ABI/version and all linking/root/layout/configuration inputs; validation-only workgraph compilation remains uncached.

Focused coverage: `python3 graphics-translator/tests/run-pipeline-cache-cpu.py` passes the workgraph and raytracing artifact single-flight/ownership checks. The existing `present-queues` fixture now also requires each native drawable to be reserved before the commit-feedback decision; its GPU execution remains blocked by the retained ARM64X runtime versus the fresh plain-ARM64 build mismatch.

### Limits

No game runtime capture, build, GPU execution or performance benchmark was performed, as assigned. Prior CORE's 18/19 ports and historical PASS receipts were read as context only. General native PSO cross-object reference sharing and broad view-pool subcase parity remain unknown; no proprietary implementation was copied. The large prior `coverage-final.json` tool read was truncated into invalid JSON, so its incomplete contents were not used as proof; fresh exact-address bodies establish the findings above.
