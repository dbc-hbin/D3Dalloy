## Cross-submission access record (follow-up in this wave)
- `src/d3d12/d3d12_command_queue.cpp`: the queue keeps `inflight_accesses_`, the recorded accesses of tracked encoders whose submission has not retired (`SubmissionRing::firstUnretired()`), plus `untracked_seq_`, the last submission containing work outside tracking. An encoder skips the queue fence only if it has no in-plan dependency, no tracked in-flight access overlaps it with a write on either side, and no untracked work may still be running. Opaque/incomplete nodes, `boundary_before` nodes (alias/global barriers, opaque neighbors, DISCARD, planning partitions) and Present mark the queue untracked. ## Stage-limited consumer barriers (follow-up in this wave)
- Each in-flight access now records its encoder's producer stages (render: vertex/fragment/tile/object/mesh plus compute/blit for helper passes; compute/blit: dispatch/blit/AS; other types: all). When an encoder's only conflicts are with tracked in-flight work, it skips the shared fence and emits `barrierAfterQueueStages(<conflicting producer stages>, <its own stages>, Device)` as a consumer barrier. This is the D3DMetal `ResolveBarriers` idea of a stage-masked barrier instead of a fence. In-plan dependencies, scopes, boundaries and untracked work still use the fence.
- New render-passes case `graph-cross-execute-producer`: a 64 MiB copy into a COMMON buffer in one ExecuteCommandLists, then a copy of its last word in the next, back to back with no CPU wait or barrier, replayed twice with the word reset in between.
