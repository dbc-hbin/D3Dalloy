**Angles checked (12), with dispositions**

1. **Handle lookup / descriptor resolution — negative (no per-invocation cost).** `resolve()` caches per handle (`dxil_resources.cpp:1178-1181`) and descriptors are materialised where the handle is created, dominating all uses (`dxil_resources.cpp:1770-1790`). Heap indexing emits one 32-byte descriptor load per lane with no waterfall (`dxil_resources.cpp:1649-1760`, comment at 1649-1652); `NonUniformResourceIndex` is honoured by construction. Compile-time only.
2. **Descriptor load width — minor waste.** `GetTextureDescriptor` always loads 4 qwords (`dxbc_binding_rootsig.cpp:658-704`); qwords 2/3 (RGB32 emulation) are unused for non-emulated textures. Per-handle, not per-access.
3. **Robustness/OOB bound checks — present per access, per lane** (candidates C1/C2). Root descriptors return `nullptr` Metadata (`dxbc_binding_rootsig.cpp:236-244`, `293`, `325`) so root-bound buffers/CBVs skip the guard. Textures can never be root descriptors (`dxbc_binding_rootsig.cpp:293`), so every texture is table/heap-bound.
4. **Null-descriptor guard — emitted twice** (candidate C4).
5. **Texture coordinate-space dispatch — 4-block branch per sample** (candidate C3).
6. **Wave ops on a 32-lane wave — negative (native).** `air.simd_sum/min/max/and/or/xor`, `air.simd_any/all`, `air.simd_ballot` used directly (`dxil_operations.cpp:2041-2057`, `2108-2137`). Helper-lane exclusion costs one `air.simd_is_helper_thread` + select per reduction (`dxil_operations.cpp:1941-1953, 2058-2060`).
7. **Wave ops that fall back to a 32-iteration lane loop** (candidate C5): i64/i8/i1 values, prefix min/max, prefix bitwise, `waveMatch`, `waveMultiPrefix*`, `waveops-include-helper-lanes` float sum/product under `preserve`.
8. **Wave size > 32 — catastrophic but rare** (candidate C6).
9. **Math precision — negative (good).** `air.fast_*` by default, plain form for `!dx.precise` and f16 (`dxil_operations.cpp:1067-1117`), `air.fma` unconditional, exact `rint` for `Round_ne`.
10. **Denorm mode — negative by default, expensive when `preserve`** (candidate C6b): every fp32 fadd/fsub/fmul/fdiv becomes a `dxmt.denorm.*` call (`dxil_operations.cpp:660-720, 789-830`); `any`/`ftz` are native.
11. **Synchronization — negative.** Barrier lowering preserves the requested memory spaces and invents no execution barrier (`dxil_operations.cpp:1547-1625`); groupshared i64 atomics use a lock loop only where DXIL has no native op.
12. **Compiler-CPU vs emitted work — separated.** `filter_by_entry = false` lowers *every* defined function (`dxil_resources.cpp:4353-4354`); `collectAnnotations/CounterHandles/HeapUsage` each walk all functions (`dxil_resources.cpp:1099-1170, 1599-1660`); `LowerVectors` has an O(N²) `for(;;)` module rescan (`dxil_converter.cpp:786-801`); `emitAIR` builds a `FunctionType` + symbol lookup per emission (`dxil_operations.cpp:254-282`); metadata parsing is linear. All of this is **PSO-creation/startup**, not per-frame GPU cost — it does not explain low FPS.

## 2. Candidates (ranked by expected per-invocation cost)

### C1 — One OOB guard branch + PHI *per lane* of every structured/raw buffer load and store
**Anchor:** `dxil_resources.cpp:802-830` (`emitGuardedAccess` → `SplitBlockAndInsertIfThen` at 812 + PHI at 821-824); per-lane loops at `dxil_resources.cpp:878-908` (`loadBufferWords`), `936-970` (`storeBufferWords`), `2244-2287` (`lowerRawBufferVector`); bound check `dxil_resources.cpp:849-853`.
**Chain:** `dx.op.bufferLoad`(68)/`rawBufferLoad`(139)/`rawBufferVectorLoad`(303) → `lowerCall` (`dxil_resources.cpp:4276`) → `lowerBufferLoad` (`2083-2100`) → `loadBufferWords` (`864`) → per used component: `bufferBytesInBounds` (`849`) + `emitGuardedAccess` (`803`). A `float4` load = 4 branches, 4 PHIs, 4 bound checks; `usedComponents` returns `0b1111` whenever a user is not an `ExtractValue` (`dxil_resources.cpp:596-605`).
**Activation:** descriptor-table or heap SRV/UAV buffer — `Metadata` (byte length) is set on exactly those paths (`dxbc_binding_rootsig.cpp:399-404, 1013-1014`). Root descriptors skip it.
**Class:** GPU, per-invocation steady state. **Confidence:** emitted structure certain; FPS weight medium.
**Existing optimization/counterevidence:** the guard exists for D3D12 semantics (OOB = read zero, write dropped, and a `select` over a null pointer would still issue a real access); when every lane is in bounds the branch is uniformly taken, which Apple GPUs handle cheaply; the byte-addressed GEP still coalesces; the reduced post-pass pipeline (`airconv_context.cpp:213-260`: SimplifyCFG, InstCombine, EarlyCSE, IPSCCP, GlobalOpt) may merge some guards.
**Minimum safe remedy:** keep the semantics but hoist one bound test per *view* (or one combined `in_bounds` mask per access) and let the per-lane value come from a `select` on the *loaded value* only where a store cannot be issued; that turns 4 divergent branches into 1.
**Falsifying measurement:** dump the lowered AIR for one real game shader and count blocks/branches/PHIs per `bufferLoad`; or GPU counters (branch efficiency, ALU/instruction count per thread) on a pass that is structured-buffer bound.

### C2 — One guard branch + PHI per constant-buffer row read
**Anchor:** `dxil_resources.cpp:1882-1891`.
**Chain:** `dx.op.cbufferLoadLegacy`(59) → `lowerCall` (`4276`) → `lowerCBufferLoadLegacy` (`1866`) → `condition = Metadata ? icmp ult(row, Low32(Metadata)>>4) : nullptr` (`1882-1884`) → `emitGuardedAccess` (`1885`). The bound is a **runtime** descriptor load, so the compare cannot fold even when `row` is constant.
**Activation:** CBV in a descriptor table or heap (`dxbc_binding_rootsig.cpp:239-244, 969-971` set `Metadata`); root CBVs return `Metadata = nullptr` (`236-244`) and are unconditional.
**Class:** GPU, per-invocation. **Confidence:** structure certain; weight medium-high because cbuffer reads are the most frequent resource access in typical D3D12 pixel shaders.
**Counterevidence:** required for D3D12 OOB-cbuffer semantics; the load is a uniform 16-byte access, so a uniform-taken branch is cheap; root CBVs are already free.
**Minimum safe remedy:** one hoisted range test per CBV covering the shader's maximum row, or a single guard around a contiguous run of row loads.
**Falsifying measurement:** count basic blocks per pixel shader for a cbuffer-heavy pass; if guards dominate block count but per-fragment instruction count and frame time are unchanged, the candidate is dead.

### C3 — Every sample expands to a 4-block dispatch that emits the sample twice, with two texture queries in the not-taken path
**Anchor:** `nt/air_builder.cpp:1410-1481` (`CreateCoordinateSample`: 4 blocks, 4-incoming PHIs at 1472-1480); `PixelSampleCoordinates` = 2 `air.get_width/height` queries + `UIToFP` + `FDiv` (`nt/air_builder.hpp:126-133`).
**Chain:** `dx.op.sample`(60)/`sampleBias`(61)/`sampleLevel`(62)/`sampleGrad`(63)/gather(73) → `lowerSample` (`dxil_resources.cpp:3216`) → `CreateCoordinateSample` (`3244-3259`) with `Pixel` = `CreateSample(PixelSampleCoordinates(...))` and `Normalized` = `CreateSample(...)`. Same shape at `3647-3660`, `3703-3706`, `3765-3768`, `4002-4005`.
**Activation:** unconditional for every sample — the branch key is the *sampler* descriptor metadata word, and every sampler path (static, table, heap) returns a loaded, never-null `Metadata` (`dxbc_binding_rootsig.cpp:259-281`). For standard D3D12 normalized samplers the pixel path is dead at runtime but still compiled.
**Class:** GPU steady state (one uniform branch + 2 PHIs per sample) plus code size/register pressure. **Confidence:** structure certain; per-sample runtime cost medium, register-pressure cost unmeasured.
**Counterevidence:** the non-normalized path is required for `D3D12_SAMPLER_FLAG_NON_NORMALIZED_COORDINATES` (`d3d12_descriptor_heap.cpp:922-931`); the identical structure already exists in the SM5 path (`dxbc_converter_base.cpp:1936-1942`), so it is not a DXIL regression.
**Minimum safe remedy:** none needed for correctness — move the pixel/normalized choice out of the per-sample site (specialise the Metal function per sampler at PSO build, or hoist one uniform test per shader) so the sample is emitted once.
**Falsifying measurement:** count `air.sample_*` and texture-query instructions per pixel shader in the metallib; if the ratio is ~2:1 with dead queries, and per-shader register count is high, the candidate is live; if the Metal compiler DCEs the dead block per function, it is not.

### C4 — Null-descriptor guard emitted at two layers for every texture operation
**Anchor:** `dxil_resources.cpp:4213-4272` (`guardNullDescriptors`, branch at `4240`), invoked for every non-barrier `dx.op` at `dxil_resources.cpp:4273-4275`; second, independent guard over every `air.*` texture/sampler call at `airconv_context.cpp:77-115` (branch at `111`).
**Chain:** dx.op texture op → `guardNullDescriptors` (branch + PHI) → lowering → `runOptimizationPasses` guard (branch + PHI, and it also catches `air.get_width/height` queries, since they take the texture handle in argument 0).
**Activation:** any texture handle with a `ResourceHandle` (all table/heap SRVs/UAVs); the AIR-level guard additionally requires the `dxmt.d3d12.root-signature` module flag.
**Class:** GPU steady state (1-2 branches per texture op). **Confidence:** both guards confirmed in code; whether the second survives the pass pipeline is **unknown** — the inner condition is the same SSA value as the outer, so a dominating-condition fold could remove it.
**Counterevidence:** Metal rejects null texture access, so the guard is load-bearing; SimplifyCFG runs right after (`airconv_context.cpp:230-236`).
**Minimum safe remedy:** nothing, unless the inner guard survives — then drop one layer.
**Falsifying measurement:** disassemble the produced metallib for one sample-heavy shader and count branches per sample; if the inner guard was folded, this candidate is dead.

### C5 — 32-iteration shuffle lane loop for wave ops without a native AIR form
**Anchor:** `dxil_operations.cpp:2012-2036` (`lane_loop`), selection predicate at `2048`; `waveMatch` loop at `2183-2193`; multi-prefix at `2294-2296`.
**Chain:** `dx.op.waveActiveBit/wavePrefixOp/waveMatch/waveMultiPrefixOp` → `lowerWave` → `reduce` → `lane_loop` when the type is i64/i8/i1, the kind has no native prefix (`min`, `max`, `and`, `or`, `xor`), or the wave is 4/8/16. Each iteration is one `air.simd_shuffle` + compare + select; `waveMatch` on a `float4` is 32×4 = 128 shuffles.
**Activation:** per op, when the above holds. **Class:** GPU steady state. **Confidence:** certain on emission; usage frequency in a game unknown.
**Counterevidence:** deliberate — 64-bit and multi-prefix values have no native AIR reduction; the loop is exact.
**Minimum safe remedy:** none cheap; a `waveMatch` on ≤32 bits could use one ballot per bit or a native `simd_match`-style sequence if AIR offers it.
**Falsifying measurement:** count `air.simd_shuffle` per shader; check whether the game's shaders use these ops at all.

### C6 — Wave size > 32 (and denorm `preserve`) turn cheap ops into loops
**Anchor:** `dxil_operations.cpp:1792-1919` (`lowerWideWave`: volatile scratch store, **two threadgroup barriers per collective**, per-source-lane volatile loads) and `dxil_operations.cpp:789-830` + `660-720` (every fp32 `fadd/fsub/fmul/fdiv` becomes a `dxmt.denorm.*` call).
**Activation:** wide wave needs a selected WaveSize > 32 *and* the `dxmt.wide-wave-threads` admission flag (`dxil_operations.cpp:548-568`, `dxil_converter.cpp:396-401`); denorm needs `fp32-denorm-mode=preserve` on the entry (`dxil_operations.cpp:794-797`).
**Class:** GPU steady state. **Confidence:** code certain; activation rare in shipped D3D12 games — these are low-probability bottlenecks.
**Counterevidence:** both are opt-in and gated by explicit proofs.
**Minimum safe remedy:** none; treat as a diagnostic if a game shader selects a wide wave.
**Falsifying measurement:** check the game's shaders for `WaveSize`/`fp32-denorm-mode` metadata before spending effort here.

## 3. D3DMetal comparison question

For a pixel shader that samples a normalized-coordinate sampler and reads three CBV rows from a descriptor table, does D3DMetal emit (a) one `air.sample` with no coordinate-space branch, and (b) any OOB guard for the CBV rows at all — or does it rely on Metal's native robust buffer access / a hoisted per-resource size test? If it emits neither, that difference (2 branches + 2 PHIs + a duplicated sample per texture op, and one branch per CBV row here) is the concrete, countable delta to chase.

**What I skipped / did not verify:** I did not read `dxil_resources.cpp:3274-4189` (sampler/anisotropy math, which contains a third per-sample branch at `3531-3532`), `dxil_operations.cpp:1120-1790` (per-op math tables), or `dxil_signature.cpp:564-1195`; the atomics64/RT/workgraph paths were excluded by scope. Every FPS weight above is inferred from emitted IR structure, not measured — the first thing to falsify is the *survival* of these branches and PHIs through the reduced pass pipeline (`airconv_context.cpp:213-260`), which nothing in this audit executed.
