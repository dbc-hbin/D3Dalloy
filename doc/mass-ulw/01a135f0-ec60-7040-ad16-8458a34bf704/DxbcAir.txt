## Retained candidates

### 1. Raw/structured buffer accesses are scalarized per component, each behind its own bounds check (and, on DXIL, its own branch)
- **Trigger:** DXBC `dxbc_converter_base.cpp:2762-2768` (load) / `2854-2860`, `2888-2894` (store) loop `EnumerateComponents(MemoryAccessMask(...))` calling `CreateGEPInt32WithBoundCheck` per component (`:3555-3565` → `icmp ult idx, trunc(Metadata)>>2` + `select ptr,null`). DXIL: `dxil_resources.cpp:884-905` (`loadBufferWords`) calls `emitGuardedAccess` per lane, which emits `SplitBlockAndInsertIfThen` + one PHI per component (`:802-829`).
- **Chain:** game `ld`/`ld_structured`/`dx.op.rawBufferLoad` → `Converter::operator()(const InstLoadRaw/InstLoadStructured)` → per-component GEP+check+scalar load → `InsertElement` → AIR → Metal. `Buffer.Metadata` is a *loaded* descriptor qword for any descriptor-table binding (`dxbc_binding_rootsig.cpp:399-404,523-…`; decode is just `trunc`, `dxbc_converter_base.hpp:505-508`), so the check cannot be folded; only root descriptors (null Metadata) skip it.
- **Activation:** any descriptor-table raw/structured buffer read/write of ≥2 components — the standard GPU-driven/bindless pattern (per-instance data in VS, cluster/instance lists in CS).
- **Classification:** steady-state GPU (issue slots, 32-bit-only memory ops, 4 dependent loads instead of one, plus 4 ALU compares; DXIL additionally pays 4 branches + PHIs).
- **Confidence:** high on code shape (confirmed by reading both paths); medium on FPS magnitude.
- **Existing optimization / counterevidence:** the null-pointer `select` keeps the load guardable but blocks vectorization at IR level; the pass list has no SLP vectorizer, so merging must come from the Metal backend (which may legally merge since stride-16 lanes are adjacent). `struct._sampler`… n/a. 16-bit lanes are intentionally split (`dxil_resources.cpp:832-840` comment: DXIL only guarantees 2/4-byte alignment), which is a genuine reason to scalarize — but not for 16-byte-aligned stride-16 cases.
- **Minimum safe remedy:** in `loadBufferWords`/`InstLoadRaw`/`InstLoadStructured`, when the read mask is contiguous from x and the element alignment (stride % 16 == 0 for structured, or the raw byte offset is 16-aligned) allows it, emit one `<4 x i32>` load with one bounds condition on the first dword, then extract; keep the per-lane path for the unaligned cases. No semantic change: the OOB result stays zero.
- **Falsifying measurement:** compile one representative DXBC/DXIL compute shader with a `StructuredBuffer<float4>` read and count `LDG`/`BSSY`-class ops and branches in the ISA (Metal shader validation / GPU trace) before and after; if the instruction count is already 1 load + 1 check (i.e., the backend merged), the candidate is dead. FPS A/B: a GPU-driven scene with and without the vectorized form.

### 2. A null-descriptor guard is inserted around every `air.*` texture access of every D3D12 shader
- **Trigger:** `airconv_context.cpp:81-115` — for modules carrying `dxmt.d3d12.root-signature` (set for all root-signature D3D12 shaders, `dxbc_binding_rootsig.cpp:1225-1226`), every declared `air.*` call whose arg 0 is a `struct._texture_*_t`/`struct._depth_*_t` pointer gets `isnotnull(handle) [& isnotnull(sampler)]` + `SplitBlockAndInsertIfThen` + PHI, executed **before** the pipeline.
- **Chain:** D3D12 PSO compile → `runOptimizationPasses` → guard per access → AIR → Metal. Each HLSL `Sample` contributes several guarded calls: the two arms of the coordinate diamond (candidate 3), each arm's `air.sample_*`, and the two `air.get_width/height` queries inside `PixelSampleCoordinates`.
- **Activation:** unconditional for D3D12 shaders (any texture fetch/query). Null descriptors are legal D3D12 state, so the check itself is a correctness requirement; the *count* of checks is the cost.
- **Classification:** steady-state GPU (control flow/code size per fetch; also compile time).
- **Confidence:** high on code; medium-low on FPS magnitude (uniform, predictable branches; nothing provably removed by the light pipeline, since the condition is a loaded descriptor value).
- **Existing optimization / counterevidence:** the guard is explicitly justified (`:78-80`) — selecting zero *after* a query still touches a null Metal texture. EarlyCSE can CSE the repeated `isnotnull` values but not the blocks. Metal may predicate or branch these uniformly; a uniform branch on Apple GPUs is cheap, so the true cost is code size and lost scheduling freedom around convergent samples.
- **Minimum safe remedy:** hoist one guard per *descriptor fetch* rather than per use (the handle is loaded once; wrap the descriptor load region once and reuse the result), and skip the guard for handles that cannot be null by construction (root descriptors, static-sampler table entries). Keep the zero-fill semantics.
- **Falsifying measurement:** dump AIR for one fixed PS with N samples and count basic blocks/branches with the guard pass enabled vs disabled (a local, non-shipped build variant); if FPS is unchanged on a texture-heavy scene while correctness breaks only for null descriptors, the guard is not a bottleneck.

### 3. Every sample site carries a pixel-coordinate/normalized coordinate diamond with a duplicated sample
- **Trigger:** `air_builder.cpp:1411-1476` (`CreateCoordinateSample`) — 4 extra blocks + 2 PHIs, emitting **both** a `Pixel()` and a `Normalized()` sample. Called unconditionally from the SM5 path (`dxbc_converter_base.cpp:1936,2031,2128,2246,2412`) and the DXIL path (`dxil_resources.cpp:3244,3647,3703,3765,4002`). The `Pixel` arm runs `PixelSampleCoordinates` (`air_builder.hpp:125-131`: 2 `air.get_*` queries + 2 uitofp + 2 insertelement + fdiv).
- **Chain:** any `Sample/SampleLevel/SampleBias/SampleGrad/Gather` with a sampler → `CreateCoordinateSample` → duplicated sample call sites in AIR → ISA.
- **Activation:** emitted always (the guard is `if (!Metadata)` on the *IR value*, and `SamplerDescriptor::Metadata` is always a loaded value: `dxbc_binding_rootsig.cpp:596-644`, `dxbc_binding_sm50.cpp:43`). The pixel arm is *taken* only for `D3D12_SAMPLER_FLAG_NON_NORMALIZED_COORDINATES` samplers (metadata bit 47 = `SamplerFlags` bit 15, `d3d12_sampler_feedback.hpp:183-197`), a rare, explicitly requested sampler.
- **Classification:** steady-state GPU (code size, a branch around a convergent operation per sample) + compile time.
- **Confidence:** high on code/activation; low-medium on FPS.
- **Existing optimization / counterevidence:** correctness requires the normalized divide for non-normalized samplers (`d3d12_sampler.cpp:143-147` sets the MTL sampler to normalized coords). The branch is uniform at runtime, so the pixel arm usually never executes; the cost is footprint and scheduling, not texture-unit work.
- **Minimum safe remedy:** when the sampler is statically known at PSO time (static samplers, `DescriptorOffset == ~0u` path at `dxbc_binding_rootsig.cpp:738-751`), emit only the arm the runtime state implies; keep the dynamic diamond only for descriptor-table samplers.
- **Falsifying measurement:** log sampler creation for the user's scene and confirm no non-normalized sampler exists; then A/B a build that omits the pixel arm for static samplers and compare FPS and ISA size on a texture-heavy pass.

### 4. `sampleNaNToZero` is forced on for every D3D12 DXBC shader
- **Trigger:** `d3d12_pipeline_graphics.cpp:825` (and 7 other sites) / `d3d12_pipeline_compute.cpp:99,203` set `common.flags = SM50_SHADER_FLAG_SAMPLE_NAN_TO_ZERO` → `dxbc_converter.cpp:885` (and the GS/TS/mesh/signature twins) → `air_builder.cpp:1530,1634,1734,1754,2102,2190,2408` → `getNaNToZero` (`air_builder.hpp:626-629`: bitcast+and+icmp+select per component), also applied to gradients (`:1754-1756`).
- **Chain:** PSO compile → flag → AIRBuilderOptions → per-sample coordinate sanitization on the dependency path to the fetch.
- **Activation:** every D3D12 SM5 shader (DXIL's `ResourceLowering` uses default options, `dxil_resources.cpp:344-345`, so DXIL sampling does *not* pay this — an asymmetry worth noting).
- **Classification:** steady-state GPU (≈3-4 vector ALU ops + added latency before each fetch).
- **Confidence:** high on activation; low on magnitude.
- **Existing optimization / counterevidence:** it is presumably a D3D12 conformance contract (D3D11 exposes the same behavior as an *option*, `d3d11_shader.cpp:17-20`, default false), which is why it is forced; the sanitize is a select, so it is cheap in isolation.
- **Minimum safe remedy:** none that is safe if the contract is required — the only honest lever is to stop paying it where it cannot matter (e.g. skip when the coordinate is provably finite, or when the sampler is point/non-comparison). Treat as "measure first".
- **Falsifying measurement:** recompile a fixed PS with `common.flags` cleared (local build) and compare ISA and FPS on a sampling-heavy scene; if unchanged, drop the item.

### 5. Compute kernels get a simdgroup barrier after every qualifying threadgroup store
- **Trigger:** `transforms/simdgroup_implicit_membarrier.cpp:30-56` — for `air.kernel` modules only, every AS3 load whose MemoryDef is an AS3 store causes `air.CreateBarrier(Threadgroup, /*SimdGroup=*/true)` to be inserted directly after that store (`:53-54`); the pass runs last in `GlobalCleanupPM` (`airconv_context.cpp:236`).
- **Chain:** compute shader with threadgroup memory → pass → barrier per store site (inside a loop ⇒ per iteration) → AIR → Metal. The pass's own FIXME notes uniformity is unhandled.
- **Activation:** any compute kernel that stores to threadgroup memory and later reads it (reductions, clustered lighting, particles, GPU-driven culling).
- **Classification:** steady-state GPU (compute serialization); insertion point is the store, so barriers are not hoisted out of loops.
- **Confidence:** high on code; unknown on frequency for the user's scene.
- **Existing optimization / counterevidence:** the barrier is inserted per *store instruction*, not per loop, and duplicates are suppressed only by `Fenced` on the defining store; the pass is deliberately "good enough for all games I know" (comment at `:38-43`).
- **Minimum safe remedy:** only insert when the load can actually be reached by another thread — e.g. keep a per-loop single barrier by hoisting to the loop preheader when the store dominates the load inside the same loop — or make the pass opt-in per kernel. Correctness-sensitive: any change needs the threadgroup-coherency tests.
- **Falsifying measurement:** dump AIR for a threadgroup-heavy CS and count `air.simdgroup_barrier` per loop; A/B FPS in a compute-bound scene with the pass disabled (correctness risk accepted locally).

Cheapest falsifier: dump AIR after the pipeline and count remaining `alloca`/load/store to the register file.

- **Startup-only items** — `metallib_writer.cpp:118-140` clone-per-export; per-shader `PassBuilder` setup; instcombine threshold raise. Not steady-state FPS.
- **Gated emulations** (integer border `air_builder.cpp:1309-1409`, volume/3D sparse sampling, anisotropic footprint `:2328-2367`, atomic64 phase, fp64, MSAA/sample-pos) — all activate only for the feature that needs them; not a general cost.
